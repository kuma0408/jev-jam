# 0013. 画面を白基調に作り直し、音に反応する粒子の背景を置く

- 日付: 2026-10-13
- ステータス: Accepted
- 種別: 工夫

## 背景

画面は、動作確認用の暗い配色の最小構成だった。ユーザーの要望は次のとおり。

- 画面の印象は大事。スタイリッシュなピアノ鍵盤を主役にしたい
- 白基調にして、緑・赤・青・紫の粒子がテンポに合わせて揺れ、拡散し、収縮する背景がほしい
- UIの洗練は、既存のデザイン用スキルを選んで使ってよい

## 決定

### 進め方

- Anthropic公式の `frontend-design` スキル（Apache-2.0）を `.claude/skills/` に導入した。
  中身を読み、デザインの進め方の指針だけであることを確かめてから使った
- 画面の改修は別のエージェントに任せ、ソロや進行の実装と並行させた。
  そのために、音と進行のエンジンを `useSession` フックに切り出し、画面はその戻り値だけを使う形に先に分けた
- 背景の演出用に、拍・ソロの音・小節の切り替わりを、音が実際に鳴る時刻で通知する `subscribe` を用意した

### 見た目

- 白地に濃い藍の文字と鍵盤。色は粒子と冒険度の印だけに使う
- 鍵盤は白鍵7＋黒鍵5の1オクターブ。次に進めるコードが鍵の上に出る。同じルートに2つ乗るときは縦に積む
- 鍵盤の上の縁に、4拍のマスが順に埋まる残り時間の表示を置いた
- 状態は色だけに頼らない。冒険度は形と個数（丸、ひし形、三角）、既定は破線の枠と「自動」、選択済みは塗りつぶしと「✓ 選択」
- 粒子は Canvas 2D。拍で全体が広がって縮み、ソロの音は音名に応じた向きへ粒を押し出し、コードが変わると主役の色が入れ替わる
- `prefers-reduced-motion: reduce` では粒子を静止させる
- 小節ごとの記録は折りたたみにして控えめにした

## 結果

PC幅とスマホ幅で、停止中と再生中の表示をスクリーンショットで確認した。
再生しながら鍵を押すと次の小節がそのコードになること、240BPMでも28秒間（30小節）エラー無く進むことを確かめた。

確認できていないこと。

- 粒子の動きの質。静止画でしか見ていないので、「ドゥンドゥン」の強さは実機で見て調整が要る
- 黒鍵の上に候補が出たときの見た目は、仮のデータで確認した
- フォントはビルド時に Google Fonts から取得する。オフラインでビルドし直すと代替フォントになる

エージェントの報告から直したこと。

- 小節の切り替わり直前に押した選択が、次の次の小節へ持ち越されることがあった。
  画面の候補は音に合わせて少し遅れて切り替わるため、その隙に前の小節の候補を押せてしまう。
  小節の頭で、選択がいまの候補に含まれるかを確かめるようにした
- 現在のコードの自動読み上げを外した。240BPMでは毎秒読み上げられてしまう

## 勉強会メモ

- 並行作業の前に「契約」（フックの型）を決めて固定した。画面担当とロジック担当が同じ作業ツリーで衝突しなかった
- 外部のスキルを入れるときは、中身を読んでから使う。今回は公式リポジトリの指針文書だけだった
- 開発サーバーは再生中のファイル編集で画面が作り直され、セッションが止まる。デモ本番は `pnpm build && pnpm start` が安全
