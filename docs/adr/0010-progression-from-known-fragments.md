# 0010. コード候補は、定番進行の断片と履歴の照合で出す

- 日付: 2026-10-13
- ステータス: Accepted（0003を置き換える）
- 種別: 設計判断

## 背景

0003では「今のコード → 次の候補」の表（遷移グラフ）を手書きした。
聴いた評価は「こなれていない」「こんなコード進行あるのか、という印象」だった。

原因は、今のコード1つしか見ていなかったこと。G7の次がCmaj7なのかEm7なのかは、
そこまでの流れ（ツーファイブの途中か、王道進行の途中か）で決まるのに、それを見ていなかった。

ユーザーから「よくある曲のコード進行をうまくつなげられないか」という案が出た。
これは最初の構想（これまでの進行から次を帰納する、木構造で幅を持たせる）と同じ発想である。
0003では木構造を「循環する進行では枝が尽きる」と退けたが、履歴の末尾と照合する形なら循環は問題にならない。

## 検討した選択肢

- 案A: 0003の表を手直しする。表が大きくなるだけで、流れを見ない欠点は残る
- 案B: 定番進行を断片として持ち、履歴の末尾と一致する箇所の「続き」を候補にする。長く一致するほど上位に置く
- 案C: 次のコードをJevに選ばせる。候補が妥当である保証がなく、ユーザーが選ぶ楽しさと役割が重なる（0003と同じ理由で不採用）

## 決定

案B。23個の定番進行（ツーファイブワン、循環、3-6-2-5、Just the Two of Us進行、丸サ進行、王道進行、
バックドア、裏コードなど）をCメジャーで持つ。

- 候補の順位: 一致の長さ → 支持する進行の重みの合計 → 冒険度の低さ
- ジャズ/ネオソウル寄りの進行は重み2、ポップス寄り（王道、カノン、小室、I-IVの往復）は重み1
- 一致の長さは4で頭打ちにする。長い進行に乗ると抜けられなくなるのを防ぐため
- 鍵盤の1つの鍵に2つの候補が並ぶことを許す（Am7とA7など）。0003の「ルートは重複させない」は撤回した
- 候補の理由として「どの定番進行の続きか」を画面に出す

## 結果

- 同じG7からでも、Dm7-G7ならCmaj7、Em7-Am7-Fmaj7-G7ならEm7が先頭に来る
- 何も選ばないと Cmaj7 → Fmaj7 → E7 → Am7 → Gm7 → C7 → Fmaj7 … と Just the Two of Us進行を回る
- 重みを入れる前は、既定の進行がカノン進行に吸い込まれた。一致が長いほど有利なので、8小節ある進行が勝ってしまう
- 聴いて自然になったかは、ユーザーの確認待ち

できていないこと。

- キーはCメジャー固定
- 4小節・8小節の区切りで解決に向かう候補を上げる処理は入れていない
- コードの種類は maj7 / m7 / 7 の3つだけ。枯葉の Bm7b5 のような和音は省いた
