# 0003. コード進行の候補は、ルールベースの重み付き遷移グラフで出す

- 日付: 2026-10-13
- ステータス: Superseded by 0010
- 種別: 設計判断

## 背景

ユーザーはこれまでの進行を踏まえて次のコードを選ぶ。候補の出し方を決める必要がある。
当初は「trie（木）構造で幅を持たせる」案があった。最初のターゲットはジャズ/ネオソウルとする。

## 検討した選択肢

- 案A: 木（trie）。定番進行を辿るには向くが、進行は循環するので無限セッションでは枝が尽きる
- 案B: 重み付き遷移グラフ。循環を自然に扱え、直近の数コードを見て重みを変えられる
- 案C: Jevに次のコードを選ばせる。候補が妥当である保証がなく、ユーザーが選ぶ楽しさと役割が重なる

## 決定

案B。機能和声（トニック、サブドミナント、ドミナント）を基本に、セカンダリードミナント、
裏コード、借用和音を「冒険度」つきで候補に加える。

UIはピアノ鍵盤とし、次のコードのルート音になれる鍵盤だけを光らせる。冒険度は色や明るさで示す。
コードの種類（m7、7など）はルールが決める。小節の終わりまでに選ばれなければ、
最も自然な候補へ自動で進めてセッションを止めない。

Jevは候補の生成には使わない。ただし各候補の「かっこよさ」を `score` で採点させ、
おすすめの鍵盤を強調する使い方は後で試す余地がある。
