# 0002. Next.js + TypeScript + Tone.js を採用する

- 日付: 2026-10-13
- ステータス: Accepted
- 種別: 技術選定

## 背景

JevのAPIキーはブラウザに出せないので、画面のほかに中継サーバーが要る。
最終的には特定ユーザーだけが使える形でデプロイしたい。

## 検討した選択肢

- 案A: Next.js + TypeScript + Tone.js。画面と中継を1つにまとめられる。Jev公式のTS SDK（`@typesafe-ai/sdk`）が使える
- 案B: Vite + React + Hono。軽くて見通しが良いが、画面と中継の2つを管理する
- 案C: 画面はTS、中継はPython（FastAPI）。music21などが使えるが、言語が2つになりデモには重い

## 決定

案A。1リポジトリ1アプリで完結し、後の限定公開デプロイも楽になる。
音の合成と拍に合わせたスケジューリングはTone.jsに任せる。

## 結果

2026-10-13に導入した。パッケージマネージャは pnpm を使う。

- Next.js 16.3.8、React 19.3.0、Tone.js 15.1.22、TypeScript 7.0.2 の組み合わせで動いた
- Next.jsは最新の16.4.0ではなく16.3.8にした。16.4.0は公開から7日未満で、
  pnpmの `minimumReleaseAge`（公開直後のパッケージを入れない安全装置）に止められたため。設定は回避していない
- `next dev` が `AGENTS.md` の末尾にNext.js用の注意書きブロックを自動で追記する。消しても再生成されるのでコミットに含めた
- Tone.jsはブラウザでしか動かないので、開始ボタンを押した時点で読み込んでいる
