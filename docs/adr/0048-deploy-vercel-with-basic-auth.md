# 0048. 当日だけVercel（Hobby）に置き、固定ID・パスワードのBasic認証で守る

- 日付: 2026-10-15
- ステータス: Accepted
- 種別: 技術選定

## 背景

勉強会の当日だけ、参加者のブラウザから触れるようにしたい。費用はできるだけ無料にしたい。
公開URLが漏れると本物のJevが呼ばれてトークンを消費するので、最低限の認証は欲しい。
ただし公開は即日で閉じるので、被害は自分のトークンを使い切られる程度。凝った認証は要らない。

## 検討した選択肢

- 案A: Vercel（Hobby）＋アプリ側のBasic認証 / 無料。Next.jsとの相性が良く、URLも安定する。東京リージョン（hnd1）を選べる / Hobbyは個人・非商用向けの規約。Vercel組み込みのパスワード保護はProプランが必要
- 案B: 手元のPCで `next start` ＋ Cloudflare Tunnel（Quick Tunnel） / 無料でアカウントも不要。止めれば即座に閉じられる / 発表中はPCを起動したままにする必要があり、起動のたびにURLが変わる
- 案C: Google Cloud Run / 無料枠に収まる / Dockerfileや課金アカウントなど、1日のための準備が重い

## 決定

案Aを採用した。URLが安定していて、PCの状態に左右されないため。
認証はVercelの機能ではなく、Next.js 16の `proxy.ts`（旧 middleware）でBasic認証をかけた。
IDとパスワードは環境変数 `BASIC_AUTH_USER` / `BASIC_AUTH_PASSWORD` で渡し、未設定なら素通しにした（手元の開発を邪魔しないため）。
画面もAPI（`/api/solo`）もまとめて守る。

## 結果

- 本番ビルドで、認証なし・パスワード違いは401、正しければ200になることをcurlで確認した。APIも認証がなければ401になった
- 本番（`NODE_ENV=production`）では `mock: true` が効かないので、公開URLで操作すると毎回本物のJevが呼ばれる
- 固定パスワードは平文比較で、総当たり対策もない。即日閉じる前提での割り切り

## 勉強会メモ

- 「Vercelのパスワード保護は有料」→ 自前で十数行のBasic認証、という小さな回避策
- Next.js 16で middleware が proxy に改名されていた話
