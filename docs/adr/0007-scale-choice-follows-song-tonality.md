# 0007. ソロの候補音は、コードの種類だけでなく曲のキーからも決める

- 日付: 2026-10-13
- ステータス: Accepted
- 種別: 苦労と解決

## 背景

確認用の画面で初めて音を聴いたところ、「ソロが少し音を外している」という感想が出た。
候補はすべてスケール内の音にしていたので、理屈の上では外れないはずだった。

原因は、コードの種類だけでスケールを決めていたことだった。
メジャーセブンスには常にリディアン、マイナーセブンスには常にドリアンを当てていたため、
Cメジャーの曲なのに次の音が出ていた。

| コード | 当てていたスケール | キーから外れる音 |
| --- | --- | --- |
| Cmaj7（I） | リディアン | F# |
| Am7（VI） | ドリアン | F# |
| Em7（III） | ドリアン | F#、C# |

実測（0005）の時点で、記録の表にCmaj7で「Gb」が出ているのは見えていた。
しかし遅延と確率分布しか見ておらず、耳で聴くまで問題と気づけなかった。

## 検討した選択肢

- 案A: コードとキー内での役割の組ごとに、使うスケールを表で持つ。分かりやすいが、コードが増えるたびに表を足す
- 案B: 構成音はコードから決め、間を埋めるテンション（9th、11th、13th）は「キーに含まれる音」を優先して選ぶ。表が要らず、借用和音にもそのまま効く

## 決定

案B。テンションごとに「標準の音」と「変化させた音」の選択肢を持ち、キーに含まれるほうを採る。
どちらもキーに無ければ標準の音にする。

結果として、Cmaj7はアイオニアン、Fmaj7はリディアン、Am7はエオリアン、Em7はフリジアン、
A7はミクソリディアンb13、E7はフリジアンドミナントが自動で選ばれる。

響きがぶつかる音（Cmaj7の11thなど）は候補から外さず、説明文で「短い経過音としてのみ使う」と伝える。
0005で、Jevが説明文のこの種の注意を分布に反映することが分かっているため。

## 結果

テストで各コードの7音を固定した。聴いて外れが消えたかは、ユーザーの確認待ち。

あわせて、聴いた感想をもとに次の調整を入れた。

- 裏拍を3連符の位置にずらすスウィング
- ソロの音色をリード楽器風の合成音に変更し、音域をテナーサックスに寄せた（本物のサックスの音ではない）
- ソロの音量を下げ、画面から調整できるようにした

## 勉強会メモ

数字（遅延、確率）だけ見て「動いた」と判断していた。音楽のデモは、耳で聴く確認を最初から工程に入れるべきだった。
ログには証拠（Gb）が出ていたのに、見る観点が無いと見えない。

余談: このADRのファイル名は当初 `0007-key-aware-...` だったが、「key」を含むパスが
Claude Codeの読み書き禁止設定（秘密鍵を守るためのもの）に引っかかり、書き込めなかった。
音楽の「キー」と秘密の「キー」が衝突した。
